> 本文件是 `skills/eval-lm-eval/SKILL.md` 的**渐进披露层**：正文只留入口一句话，长内容在这里。
> 本题对「评测侧必须施加同一次假量化」这条**红线**的说明（**落点见 §1 的现状**）。
> 纪律：包名/版本/解释器路径的唯一落点是 `config/tasks/<任务名>.yaml` 的 `eval.lm_eval.*`；
> 口径常量的唯一落点是任务配置 `eval.protocol.*` 与 `<轮次>/criterion.yaml` 的 `eval_protocol.*` —— **本文件不复述任何具体值、不含模型名**。

## 1. 为什么评测侧也必须施加同一次假量化

QAT 是**假量化**：训练前向把权重/激活 round 到目标格式再解回来，**存下来的 ckpt 仍是主权重精度**
（框架侧 `master_weight_dtype` 那条注释解释的就是这件事）。所以用普通精度推理去评测它，测到的是
「训练过、但**没量化**」的精度 —— 不是方案的精度。

⇒ 推理端必须把**同一次 rounding 再施加一遍**（理由：(b) 模型加载与量化补丁不可泛化 ⇒
进任务目录 ＋ skill）。

**红线**：训练侧与评测侧必须是**同一个东西**；两侧不是同一次舍入，聚合差就不能归因给方案。

★ **现状（本轮不做，照实记）**：评测侧的量化补丁**尚未移植**到本工程 ——
任务目录 `drivers/lm_eval_driver.py` 只负责**拼 lm_eval argv 并执行**（真命令形状），
它**不施加任何量化补丁**。所以在此之前，本工程跑出来的评测数字是**主权重精度**的数字，
**不许**当成某个低精度方案的精度结论；要出精度结论，先落地评测侧的量化补丁。

## 2. 驱动 ↔ 环境变量：逐项对齐，且「下发了」≠「被读到了」

这是评测侧最贵的一类静默故障，已发生过一次真事故：

> 某个开关被下发给了**不认它的驱动**（该驱动源码里**根本没有那个字符串**）⇒ 开关被**静默丢弃**：
> 训练用的是修过的内核、评测用的是没修的。实测差**远在噪声底之下** ⇒ 看起来像「修了没用」，
> 真相是「**评测根本没修**」。

因此：

1. **驱动选择从 env 反推**，不要手写「方案 → 驱动」表（方案一多必然漏项）。
2. **「生效」的定义要卡住**：形如 `X=0` 的**无操作值不算生效**，不要为一个无操作的事换驱动 ——
   换驱动可能**连带打开一个从没要求过的开关**。
3. **对齐表逐项核**：`scheme_resolved.json` 展开的每个取值 ↔ 驱动实际读的键 ↔ 驱动里施加的取值，三者一一对上。
   对不上就停下报错，**不许硬跑**。
4. 认不出来就**报错**，不要静默继续（同一个 env 喂给「会自证」的那份驱动会响亮报错，喂给「不会自证」的那份会 exit 0 往下跑，
   产出一个**贴着方案标签**的数字）。

## 3. 自证标记：机制生效的直接证据

每份驱动都必须打印一条**自证标记**（说明「假量化真的装上了」）。要求：

- 标记字符串**写进任务目录驱动的 README／`changes.md`**，评测命令与 `evidence/` 里能对到它；
- **先确认标记真的会打印**：有的驱动把标记包在详细模式开关里 ⇒ 不设那个开关，日志里就没有标记，
  检查会把「假量化已生效」判成**未生效**（一次**假失败**）。判据：跑一次最小评测，日志里**必须看到**标记。
- 没有标记 ⇒ 等于没有「机制生效验证命令」，不许交 `TEST_READY`／`EXPERIMENT_DONE`。

## 4. 已证明必须的评测口径项（值只在配置/判据里，这里只列**项**）

| 项 | 要求 | 为什么 |
|---|---|---|
| 模板（`--prompt-type`） | 由任务配置给，两侧一致 | 口径不对，两个数不是同一个东西 |
| KV cache | 按任务配置开 | 不开会让单样本耗时高一个量级，评测跑不完 |
| `max_gen_toks` | 基线与目标**必须同值** | 光换这个数就能比大多数方案的效果还大 |
| 样本上限（`limit`） | 与 `criterion.yaml` 的 `eval_protocol.limit` 一致 | `null` = 全量；写数字 = 子集（决定这条结论覆盖多少样本） |
| 并行与设备声明 | TP/PP/DP 与设备可见性显式声明 | 不声明设备会被守卫拦（`_common.sh`），也是复现的一部分 |
| tied embeddings | 按任务配置（不许凭习惯加开关） | 有些模型是 tied embeddings，加了开关就换了个模型 |

**判据**：`<轮次>/criterion.yaml` 的 `eval_protocol.{dataset,prompt_type,mode,max_gen_toks,limit,batch_size}` 与
任务配置 `eval.protocol.*` **逐项一致**；有任一项不一致 ⇒ 退出 `6`（评测侧无效），本轮不产生精度结论。

## 5. 落盘与「能独立复现一次评测」

评测原始输出**原样**进 `<轮次>/evidence/`：stdout/stderr、结果文件、命令原文、包版本、驱动 sha、口径清单。
随后交给 `runtime/metrics.py` 抽数（**数字只由抽取器算**，报告只引用）。

**判据**：只看 `evidence/` 就能独立复现这次评测（命令 ＋ 版本 ＋ 驱动 sha ＋ 口径四项齐全）。

## 6. 离线可验 vs 必须上真机验

设计与移植阶段优先做**不占卡**的验证（语法编译、`--help`、补丁模块自证、旋转恒等式一类纯数值检查）；
真正跑评测必须上真机。**判据**：把「离线已验」与「必须真机、尚未跑」分开写进 `evidence/`／`test.md`，
不许用离线绿冒充真机绿。

## 7. 目录与导入

驱动与补丁目录**不要**用与已安装包同名的目录名（同名易被读成「遮蔽」；实测：无 `__init__.py` 的目录是命名空间包，
抢不过真包，但只要有人顺手加一个 `__init__.py` 就会变成真遮蔽）。
启动方式：**用绝对脚本路径**启动驱动，`sys.path[0]` 就是驱动目录，`import <评测包>` 仍解析到真包。
