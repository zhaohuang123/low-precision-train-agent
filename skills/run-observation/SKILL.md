# 读观察（`run-observation`）

## 0. 什么时候用 / 什么时候不用

- **用**：读完一段执行（冒烟或整轮）后，判「发生了什么、该走哪条路」。
- **不用**：判「方案的机制对不对」（`code-change`）；判「精度够不够」（`report-and-conclusion`，读冻结判据）。
- **红线**：**没启用 ≠ 搜了没搜到**；两者在日志里长得一样，必须用直接证据区分。

## 1. 开工前要读的文件（路径 + 字段名）

| 读什么 | 取哪些字段 | 为什么 |
|---|---|---|
| `<轮次>/evidence/**` | 逐行日志、进程元数据、退出码 | 原始证据；只读 |
| 任务配置 `stop_conditions.*`（只读） | `{max_steps,loss.jump_factor,loss.rel_to_best,loss.min_points,wall_clock_hours}` | 早停与墙钟阈值的**唯一落点**（0.18.18 起），不许自己发明 |
| `<轮次>/patches/framework_{head,status}.{before,after}` | 前后快照 | 判框架是否已还原干净 |
| `runtime/README.md` | 退出码表与「已知坑」 | 归类失败的依据 |

## 2. 步骤（每步带判据）

1. **读退出码并归类**：`0` 成功（**含平台早停 `stop_kind=converged`**）／`1` 运行期失败／`2` 约定或门不过／`5` 训练侧无效（发散、非有限值、**墙钟超时**；**不含平台早停**）／`6` 评测侧无效（口径不全、驱动异常）。
   *判据*：写出归类与依据行；不许把 5/6 含糊成 1。
2. **判在线早停**：命中时记下**哪个阈值、第几步、什么数值**（例如相邻步 loss 比值、末步/最好步比值、量化误差）。
   *判据*：三项齐全；执行器必须已杀掉**整个进程组**（残留进程要单独确认）。
3. **判墙钟超时**：任务配置 `stop_conditions.wall_clock_hours` 到点即停，记录已跑步数与产出位置；**归类到 `5`**（训练侧无效 —— 与发散同一处置路径：保险丝触发 ⇒ 杀进程组 ⇒ 训练没跑完）。
   *判据*：停止原因与步数落 `evidence/`；半成品产物明确标注「不完整」。
4. **判离线 loss 轨迹**（只在本轮**有训练段**时有这件事）：至少 `loss.min_points` 个点才下结论；看形状（单调/平台/发散/抖动）而不是看单个点。
   *判据*：点数与形状都写出来；点数不足 ⇒ **不下结论**（写 `null` ＋ 理由）。
   ★ 没有训练段（基线轮只跑 convert/eval）⇒ `metrics.json` 记 `training.observation: not_applicable`，
   报告里写「本轮无训练段」，**不要**把它说成"点数不足"或"训练没跑对"。
5. **按 `stop_kind` 分两种处置**（留痕在 `evidence/early_stop.triggered`）：
   - `converged`（平台早停）⇒ 本轮**结论有效**，报 `EXPERIMENT_DONE`，但必须写成**停止轮次**：
     「停在第 N 步、未跑满 `max_steps`」；训练侧 loss 不得与跑满轮次直接比，下游评测可以比。
   - `invalid`（发散/非有限值/墙钟超时）⇒ 报 `EXPERIMENT_INVALID`：写清失败证据 ＋ 触发阈值与步数 ＋ **重跑要改什么**。
   *判据*：「要改什么」是可指名的**一处**改动（自变量或配置）；说不清就不许原样重跑。

## 3. 模板与命令（可直接复制）

```text
退出码：<0|1|2|5|6>   依据：<日志行 / 命令>
早停：阈值=<stop_conditions 里的字段名>  值=<…>  步=<…>  触发值=<…>
进程：主进程 <pid> 已杀 | 残留进程组：<有/无>（有则列出）
轨迹：点数=<…>（min_points=<…>）  形状=<单调/平台/发散/抖动>
结论去向：<EXPERIMENT_INVALID | 继续抽数>
```

## 4. gotchas（症状 → 正确动作）

1. **只看退出码不看日志** → 症状：把 OOM 当「参数不对」。正确动作：退出码＋关键日志行一起看。
2. **早停只杀父进程** → 症状：卡被残留进程占住，下一轮莫名 OOM。正确动作：杀整个进程组并确认。
3. **点数不足就下结论** → 症状：结论反复。正确动作：不足 `loss.min_points` 就写 `null` ＋ 理由。
4. **命中无效早停后原样重跑** → 症状：浪费一轮、得到同样结果。正确动作：报 `EXPERIMENT_INVALID` 并指出要改什么。
   （`converged` 不在此列：它是合法收工，重跑它才是浪费。）
5. **同一次失败既报训练无效又报评测无效** → 症状：归因混乱。正确动作：按**首个**关键失败点归一类。

## 5. 校验回路（自查「我真的做对了」）

- 退出码归类有依据行；早停三项（阈值/步/数值）齐全。
- 残留进程已确认清理；框架 patch 的 before/after diff 为空。
- `loss.min_points` 满足；未满足已明确写「不下结论」。
- `EXPERIMENT_INVALID` 时写清了可指名的一处改动。
