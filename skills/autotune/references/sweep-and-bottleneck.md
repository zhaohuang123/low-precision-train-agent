`axis` 的枚举（受控块字段）：`precision`｜`scale_granularity`｜`rotation`｜`layer_policy`｜`clamp`｜

## 2. 参数空间怎么写（每条轴四件事）

```yaml
axes:
  - name: <轴名>                # 只在上面枚举的轴里
    candidates: [<取值>, <取值>] # 取自 design.md 与该轴在框架里的取值域
    cost_multiplier: <倍数>      # 相对基线步时的倍数（你自己实测/估算，并写依据）
    expected_signal: <大|中|小>   # 依据：历史结论或知识库条目
fixed:                          # 必须显式写死，否则不算「受控」
  <变量>: <取值>
budget_cap:
  max_runs: <n>
  npu_hours: <n>
```

**判据**：一条轴的 `cost_multiplier` 与其它轴差得远（例如 1.0 vs 4.0）⇒ **不要混进同一个扫描批次**：
不同成本档的结果不可直接排序。

**落点**：参数空间没有独立文件名；轮次目录的法定文件是 `design.md`／`criterion.yaml`／`round.env`，
tester 产出 `test.md`（§5.2；任务目录/轮次约定 P4c 已落盘，实物见 `experiments/<任务名>/README.md`）。因此参数空间写进 `<轮次>/test.md`
（太长就落 `<轮次>/evidence/` 并在 `test.md` 里指路径）。

## 3. 档内噪声：先量尺，再读数

**量法**：把**同一配置原样跑第二遍**（`seed` 与训练超参是**钉死**的，不许换 seed），取两个**聚合指标**的绝对差。
它量的是「钉不死的残余」（评测抖动、内核非确定性）。**不是**逐题配对，**不是**置信区间 —— 那套是被本工程刻意否掉的机制。

**判据**：
- 档内最好与次好之差 **>** 本档噪声 ⇒ 有信号，可以进收窄。
- 档内最好与次好之差 **≤** 本档噪声（或噪声未实测且测不出）⇒ **换轴**，并写明「为什么这一轴在本预算下没有信号」；
  继续加候选只会把噪声测得更准。
- 所有轴的档内差异都 ≤ 噪声 ⇒ 交 `TEST_READY` 前先写明「本预算下无法分辨」，或交 `TEST_BLOCKED`；
  **不许**交一个靠小数列排序的候选。

## 4. 瓶颈三分类（扫参前先答「是哪一类」）

| 分类 | 典型症状 | 需要的证据 | 归属 |
|---|---|---|---|
| 数值问题 | loss 跳变/NaN、精度骤降、饱和 | 完整 loss 轨迹 ＋ 触发步的数值（相邻跳变倍数） | 方案/内核 |
| 实现缺陷 | 机制没生效、两侧不一致、静默 fallback | 探针计数、两侧逐项对齐表、`file:line` | developer |
| 资源限制 | OOM、吞吐不达标、超时 | 显存峰值、吞吐对比、耗时分解 | **只报告**，交配置调整 |

**判据**：
- **资源限制这一类只报告、不判对错**；不能靠自己调超参把「实现缺陷」绕过去。
- 每条问题都要带「**改成什么样才算过**」；写不出来的不许提（那只是一句抱怨，developer 无从行动）。
- 采不到的类别就写「未采集 ＋ 原因」，**不许用形容词代替数字**。

## 5. 冒烟五项（不许跳过，也不许用大预算赌）

能起｜loss 有限（前若干步每步 `isfinite`）｜**无异常跳变**（相邻步上升比不超过判据里的阈值）｜不 OOM｜
步数/几何与配置**逐项相同**。

**为什么「loss 有限」单独不够**：本工程记录过一次真实形态 —— 相邻两步 loss 从 `2.02` 涨到 `18.4`（`9.09` 倍），
**两个值都是有限值**，只查 NaN/Inf 的检测完全没触发，于是白跑了一次完整训练。所以冒烟阶段就要连**跳变比**一起看。
（历史教训只搬结论；阈值从**任务配置**的 `stop_conditions.loss.*` 读，不在本文件写死。）
