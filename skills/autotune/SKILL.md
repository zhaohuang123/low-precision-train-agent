# 测试与寻优（`autotune`）

## 0. 什么时候用 / 什么时候不用

- **用**：`CODE_READY` 之后、交给 experimenter 之前：先证明**能跑**，再找**往哪扫**。
- **不用**：改代码（`code-change`）；跑完整三段与出结论（`experimenter`）；判改动是否正确装上（那是 developer 在 `changes.md` 里给的验证命令，你只**复跑**它）。
- **红线**：冒烟不通过**不许**进入扫参；测试暴露的是代码缺陷时**不许靠调参绕过**。

## 1. 开工前要读的文件（路径 + 字段名）

| 读什么 | 取哪些字段 | 为什么 |
|---|---|---|
| `<轮次>/changes.md`（只读） | 机制生效验证命令、回滚方式、被改文件 | 第 1 步要复跑它 |
| 任务配置 `stop_conditions.*`（只读） | 早停阈值、`wall_clock_hours`、`max_steps` | 冒烟与扫参的预算与阈值**唯一落点**（0.18.18 起），不许自己发明 |
| `<轮次>/criterion.yaml`（只读） | `success.*`／`falsification`／`budget.{runs,train_iters,npu_hours}` | 判定与计划量 |
| `<轮次>/scheme_resolved.json`（只读） | 展开后的实际取值＋来源 | 复现读它，不读块 |
| `<任务目录>/{run.env,train.sh,convert.sh,eval.sh,commands/}` | 三段命令与变量约定 | 扫参靠改变量/追加 argv 片段，不改命令本体 |
| `runtime/{executor.py,resources.py,_common.sh}` | 退出码表、定卡来源、四机制 | 读观察 |

## 2. 步骤（每步带判据）

1. **复跑机制生效验证**：照 `changes.md` 的命令确认机制真的装上了。
   *判据*：输出能直接证明生效；证不出 ⇒ 交 `TEST_BLOCKED` 回 developer。
2. **冒烟（5 步级、分钟级）——只有本轮有训练段才做**：能起、loss 有限、无异常跳变、不 OOM、步数与配置对得上。
   ★ 基线轮／只评测的轮次**没有训练段**：跳过冒烟，改做「转换能出权重 ＋ 评测能跑出数字」的 1 条集冒烟。
   ★ **落点分开**：冒烟一律 `LP_EV=<轮次>/evidence/smoke` 起（日志、`exec.json`、`loss.txt`、
   探针产物、评测默认落点全跟着它进 `smoke/`）。冒烟与正式跑写的是**同一个文件名**，不分开的话
   10 步那份一留下，正式跑只要没写新文件，抽数就会把 10 步的数当成本轮实测。
   *判据*：五项逐条有观察证据（退出码＋日志行）写进 `<轮次>/test.md`；任一项不过 ⇒ `TEST_BLOCKED`。
3. **量档内噪声（先量尺，再读数）**：同一配置重跑两次，取**聚合差**作为本档噪声。
   *判据*：写出这个聚合差；它是后面「差异算不算信号」的唯一尺子（**不是配对的置信区间**）。
4. **粗扫 → 收窄 → 复验**：
   - 粗扫：每个候选只跑最小可区分预算；
   - 收窄：只在有信号的档内加密；
   - 复验：对最优候选重跑，确认差异大于档内噪声。
   *判据*：同一成本档内**必须有可区分信号**；没有 ⇒ **换轴**（换自变量维度）并写明「为什么这一轴没信号」，**不许**继续堆候选。
5. **产出候选配置**：`<轮次>/test.md` 写冒烟结果、候选配置、run 命令、预期耗时、瓶颈三分类（数值／实现缺陷／资源限制，各带证据）；
   `<轮次>/round.env` 写本轮变量覆盖（只改变量值／追加 `LP_*_EXTRA_ARGS`）。
   *判据*：experimenter 照抄即可开跑；`round.env` 没有重定义整条命令、没有删任务级变量。
6. **交接**：`TEST_READY`（或 `TEST_BLOCKED`）。

## 4. gotchas（症状 → 正确动作）

1. **拿大预算赌一个没起的配置** → 症状：白烧卡。正确动作：冒烟先行（5 步级）。
2. **档内没有可区分信号还在堆候选** → 症状：多轮累计仍无结论。正确动作：换轴，并写明原因。
3. **把噪声当信号** → 症状：结论反复。正确动作：先量「同配置重跑两次的聚合差」，差异必须大于它。
4. **靠调参绕过代码缺陷** → 症状：这一轮过了，下一轮同类缺陷再现。正确动作：交 `TEST_BLOCKED`，由 developer 修。
5. **自己发明阈值** → 症状：配置与实跑不一致。正确动作：早停/预算阈值只从任务配置 `stop_conditions.*` 读。
6. **在轮次目录放脚本副本** → 症状：`check_round_layout.py` 退出 `2`。正确动作：轮次只放 `round.env` 与 `hooks/*.sh`。

## 5. 校验回路（自查「我真的做对了」）

- 冒烟五项都有证据；档内噪声已量；每个候选带 run 命令与预期耗时。
- `round.env` 只改变量值/追加 argv，没有重定义命令、没有删除任务级变量。
- 轮次目录里没有 `train.sh`／`convert.sh`／`eval.sh` 副本。
- 结论里没有自己算的数字（数字最终由 `runtime/metrics.py` 抽）。
