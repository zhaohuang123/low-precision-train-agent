## 不放什么

- **变量类补丁**（本轮方案要实现的东西，只有实验臂挂）：它在轮次归档 `<轮次>/patches/` 里。下一轮还要用同一个变量 ⇒ **引用，不复制**（`ref: ../R-000X/patches/<文件>`）；它进不进这里，看的是「基线要不要也挂」，不是「用了几轮」。
- **改了哪些文件的清单**：那是 `<轮次>/changes.md` 的事；这里不重建它。
- **完整文件复制 / 大段代码**：只留 `file:line` 与「改哪里能达成什么」。

## 怎么沉淀到这里（**探针/工具是手段，手段每轮都要挂**）

一份补丁的走法按**它是不是手段**决定，跟"用了几轮"无关：

| 段 | 手段类（探针/观测/工具/bugfix） | 变量类（本轮方案要实现的东西） |
|---|---|---|
| 出生 | 为某一轮写的，先落在 `<轮次>/patches/` | 落在 `<轮次>/patches/`，往往就到此为止 |
| 判定 | **基线也要挂** ⇒ 它是手段 | **只有实验臂挂** ⇒ 它是变量 |
| 去向 | 提炼进本目录，之后**所有轮次直接引用这里那一份** | 留出生那一轮；下一轮还要用就 `ref: ../R-000X/patches/<文件>` 引用 |

**两条纪律**：

1. **沉淀不搬原件。** 进这里的是**提炼过的版本**（把某个任务的具体取值变成入参，例如采样步表走
   `QAT_QSNR_STEPS` 这类显式入参），不是轮次里那份的拷贝。原件原地不动 ⇒ 老轮次永远可复现。
2. **去任务化是卫生要求，不是门票。** 手段类补丁里写死了某个任务的取值（`qat-qsnr-probe/core` 的采样步表
   就是一例）**不改变它是公共补丁的身份** —— 它该留下，只是该被参数化。判"是不是公共"看基线挂不挂，
   判"写得好不好"才看有没有写死取值。

## 三处链接关系（每个事实一个家）

1. `knowledge/techniques/<技术>.yaml|.md` 的 `patch_ref:` → 指向**本轮 patch**（轮次归档）与/或 **`patches/` 的公共 patch**；两个都指就写成清单。
2. 本目录的**理解笔记** → 指向它描述的**具体 `file:line`**（不是指向 patch）。
3. 轮次归档里的 patch → 在 `<轮次>/changes.md` 里被引用一次（改了哪些文件、怎么验的）；**不把 patch 内容抄进知识条目**。

## 相关铁律（回指，不复述）

- 框架目录本身**永不提交改动**（`git status --porcelain` 为空）；改动以 patch 挂载、跑完还原、前后快照 diff 必须为空。
- 用 `git worktree` 按需切干净工作树，patch 只 apply 到工作树，起点钉在任务配置的 `train.framework_head`。
- 挂/还原的机制实现是 `runtime/framework_patch.sh`（**P5 已交付**：`apply`／`restore`／`verify`／`roundtrip` 四子命令，含前后快照 diff 校验）；纪律全文见 `AGENTS.md` §2 第 1／5 条与 `runtime/framework_patch.sh verify`。
